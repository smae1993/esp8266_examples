# Queue: ارسال پیام بین Taskها

## هدف آموزشی

یاد بگیری چطور یک Task داده را به Task دیگر **ارسال** کند، بدون اینکه دو Task هم‌زمان به یک متغیر دست بزنند. الگوی رایج **Producer / Consumer** را هم می‌بینی.

## ایده‌ی ساده

فرض کن یک **صندوق پست** بین دو نفر داری. یک نفر نامه (فرمان) می‌گذارد و نفر دیگر آن را برمی‌دارد و می‌خواند. صندوق ظرفیت محدود دارد و اگر پر باشد، فرستنده صبر می‌کند.

## مفاهیم کلیدی

| تابع | کاربرد |
| --- | --- |
| `xQueueCreate(تعداد, اندازه)` | ساخت صف با ظرفیت مشخص |
| `xQueueSend()` | ارسال یک کپی از داده به صف |
| `xQueueReceive()` | دریافت یک کپی از داده از صف (و حذف آن از صف) |

## نکته‌ی مهم: کپی می‌شود

`xQueueSend` **کپی** داده را داخل صف می‌گذارد، نه خود متغیر را. بنابراین بعد از ارسال می‌توانی همان متغیر را دوباره تغییر دهی بدون اینکه پیام قبلی خراب شود.

## ساختار پیام

```c
typedef struct {
    int relay_id;   // شماره‌ی رله
    int turn_on;    // 1 = روشن، 0 = خاموش
} RelayCommand;
```

## نحوه‌ی کار

- **`network_task`** (فرستنده): هر ۲ ثانیه یک بار فرمان روشن و خاموش کردن رله‌ی ۱ را در صف می‌گذارد.
- **`relay_task`** (گیرنده): منتظر می‌ماند تا پیامی برسد و آن را چاپ می‌کند.
- `xQueueReceive` با `portMAX_DELAY` تا رسیدن پیام **بلاک** می‌شود، یعنی Task مصرف‌نمی‌کند تا زمانی که داده‌ای باشد.

## خروجی انتظار

```text
Relay 1: ON
Relay 1: OFF        ← حدود ۲ ثانیه بعد
Relay 1: ON
Relay 1: OFF
...
```

## اجرا

در [main/main.c](../../main.c):

```c
#include "queue_example.h"

void app_main(void)
{
    queue_example_run();
}
```

## تمرین

1. به ساختار `RelayCommand` یک فیلد `delay_ms` اضافه کن و مدت تأخیر را از فرستنده بفرست.
2. ظرفیت صف را از `5` به `1` کم کن و ببین `network_task` چه موقع منتظر می‌ماند.
3. یک رله‌ی دوم اضافه کن و فرمان‌ها را برای هر دو رله بفرست.

## صف در مقابل متغیر مشترک

| | متغیر مشترک + Mutex | Queue |
| --- | --- | --- |
| انتقال داده | همه یک متغیر را می‌خوانند و می‌نویسند | داده کپی و منتقل می‌شود |
| ترتیب | معمولاً مشخص نیست | ترتیب ورود حفظ می‌شود (FIFO) |
| مناسب برای | وضعیت مشترک کوچک (مثل شمارنده) | پیام‌ها و فرمان‌ها |
