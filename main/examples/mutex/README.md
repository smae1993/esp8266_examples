# Mutex: محافظت از داده‌ی مشترک

## هدف آموزشی

یاد بگیری چرا وقتی دو Task یک متغیر را تغییر می‌دهند، به **Mutex** نیاز داری، و چطور با آن از خرابی داده جلوگیری می‌کنی.

## ایده‌ی ساده

فرض کن یک **دفترچه‌ی حساب مشترک** داری و دو نفر باید مقدارش را افزایش دهند. اگر هر دو همزمان عدد را بخوانند، یکی را افزایش دهند و بنویسند، یکی از افزایش‌ها گم می‌شود.

**Mutex** مثل **کلید یک اتاق** است: فقط کسی که کلید دارد می‌تواند داخل شود. بقیه باید صبر کنند تا کلید برگردد.

## مشکل: Race Condition

عمل `total++` در ظاهر یک خط است، اما داخلش سه مرحله دارد:

1. مقدار `total` را بخوان
2. یک واحد به آن اضافه کن
3. نتیجه را برگردان

اگر FreeRTOS در وسط این سه مرحله Task دیگری را اجرا کند، هر دو Task ممکن است یک مقدار را بخوانند و نتیجه اشتباه شود.

## مفاهیم کلیدی

| تابع | کاربرد |
| --- | --- |
| `xSemaphoreCreateMutex()` | ساخت یک Mutex |
| `xSemaphoreTake()` | گرفتن قفل (اگر آزاد نباشد صبر می‌کند) |
| `xSemaphoreGive()` | آزاد کردن قفل |

## نحوه‌ی کار

```c
if (xSemaphoreTake(counter_mutex, portMAX_DELAY) == pdTRUE) {
    total++;                    // کار با داده‌ی مشترک
    int current = total;        // یک کپی محلی بگیر
    xSemaphoreGive(counter_mutex);   // قفل را زود آزاد کن

    printf("%s: total = %d\n", name, current);   // چاپ خارج از قفل
}
vTaskDelay(pdMS_TO_TICKS(500));   // استراحت خارج از قفل
```

- دو Task با نام‌های `worker_A` و `worker_B` هر ۵۰۰ میلی‌ثانیه `total` را یک واحد زیاد می‌کنند.
- قفل را فقط برای مدت کوتاهی که به داده‌ی مشترک دست می‌زنی نگه می‌داری. **چاپ کردن** و **تأخیر** خارج از قفل انجام می‌شوند تا بقیه‌ی Taskها زیاد معطل نشوند.

## خروجی انتظار

```text
Task A: total = 1
Task B: total = 2
Task A: total = 3
Task B: total = 4
...
```

ترتیب چاپ ممکن است کمی متفاوت باشد، اما شماره‌ها همیشه پشت سر هم و بدون تکرار هستند.

## تمرین

1. خطوط `xSemaphoreTake` و `xSemaphoreGive` را موقتاً کامنت کن و ببین آیا عددها درست پیش می‌روند. این کار را چند بار تکرار کن.
2. چرا `printf` را بیرون از قفل گذاشته‌ایم؟ چه تفاوتی دارد اگر آن را داخل قفل بگذاریم؟
3. تعداد Taskها را به سه یا چهار افزایش بده و ببین Mutex چطور همه را یکی‌یکی به داده‌ی مشترک می‌رساند.

## تفاوت Mutex و Binary Semaphore

- **Mutex** برای **محافظت از داده** است. همان Task که قفل گرفته باید آن را آزاد کند.
- **Binary Semaphore** برای **اعلام رویداد** است. یک Task علامت می‌دهد و Task دیگر آن را می‌گیرد. (مثال بعدی را ببین.)
